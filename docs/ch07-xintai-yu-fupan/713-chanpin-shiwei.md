# 产品思维与学生思维

面试准备的那阵子，我跟一位博士生聊复习规划。他说了一句让我愣住的话：**做科研，不要为了学什么而去学什么。**

他说，很多人（包括他自己带过的学弟学妹）会先花一大块时间，把某个方向的课程视频从头刷到尾，觉得「学扎实了」再动手。结果视频学完就忘，真上手遇到问题，还是不知道该用哪一块。不如反过来：先有一个要解决的问题，缺什么补什么，学了立刻用上。

我当时没接话，因为我心里正心虚——我就是那个囤了一堆课程视频的人。

## 自嗨式学习的真相

我把自己的学习方式复盘了一遍，发现它有个共同特征：**只有输入，没有产出。**

看了很多课，读了很多资料，过程里挺有充实感，甚至有点自我感动。但回头一盘点，说不出自己做出了什么：没有一段拿得出手的代码，没有一篇整理完的笔记，面试时被追问两句就露馅。学到的东西在脑子里糊成一团，对下一步的行动没有任何帮助。

这种状态可以叫「自嗨式学习」：以「我看过了」「我学过了」为完成标准，从不检验东西有没有沉淀下来。它本质上是学生思维的惯性——十几年应试训练养成的习惯，以为「学」本身就是目的，学得越全面越安心。

## 产品思维是什么

跟它相对的，我姑且叫产品思维：**以「解决问题」为单位组织学习，并且要求每一段学习都留下可见的产出。**

做一个产品的人不会先「学完所有技术再动手」，而是先做一个能跑的最小版本，缺什么学什么。放在科研和学习上就是：

- 先明确要解决的问题：跑通一个模型、复现一篇论文、写完一个功能。
- 顺着问题去学：需要哪个知识点就学哪个，学到能用就停。
- 学完必须留下资产：一段能跑的代码、一篇能复用的笔记、一个能演示的东西。

关键是第三条。没有产出，学习就没有验收点，自嗨就无从识别。有了产出，「学没学会」变成一个可以客观回答的问题——代码跑没跑通、笔记能不能讲清楚，骗不了人。

## 视频课的坑，以及怎么绕

具体到我最依赖的视频课，问题更直接：看视频是被动输入，看到的都是别人的讲解和零散的代码片段，印象浅，落不了地。

我后来换成笨办法，分三步：**先读原始材料（文档、源码），再理解，最后手写复现。** 手敲那一步特别重要——敲的过程里，每一个「我以为我懂了」的地方都会现出原形。慢是慢很多，但敲完的东西真的是自己的，隔一个月还能讲明白。

这不是说视频完全没用，入门导览它还行。但从「知道」到「会」，中间那段路没有捷径，只能自己走。

## 换个角度想面试

想通这一层，再回头看面试，反而松了口气：面试官想听的从来不是「你学过什么」，而是「你解决过什么问题、怎么解决的、留下了什么」。这个问题的答案，只能用产品式的学习方式攒出来——一段段真实的、有产出的经历。

学生思维追求「全面的准备」，产品思维追求「拿得出手的东西」。保研这场信息战里，后者便宜得多，也有效得多。

## 一个当天能做的动作

挑一样你最近「学过」的东西，问自己：它留下产出了吗？没有的话，今天就把它做成一个——半页能讲清楚的笔记，或者一段能跑的代码，都行。
