# 先跑一轮，再让下一轮变聪明

我最近意识到一件事：我做事的默认姿势，一直是「人类规划者」，不是 agent。人类规划者想的是——先把这件事在脑子里想清楚，再动手；agent 想的是——先动一步，看环境返回什么，再决定下一步。两种姿势看起来只差一个「先想还是先动」，跑出来的轨迹完全不一样。

## 仿真是不准的

人习惯在脑子里先跑一遍完整的仿真，等仿真通过了才允许自己真的动手。可仿真是不准的：你脑子里的模型，是用你现在的先验搭起来的，而你现在的先验，恰恰因为没做过这件事才这么稀薄。用一个稀薄的模型去预测一件复杂的事，再用预测结果说服自己「还没准备好」——这不是谨慎，这是用规划的姿态回避采样。

论文第一次被拒之后，我坐在那儿想了整整两天怎么改，越想越觉得每个改法都有漏洞，最后什么都没动。真正让稿子开始往前走的，是我硬着头皮先把摘要按新期刊的口味重写了一段，发给合作者。他一回信，我立刻知道哪里跑偏了、哪里其实还行、哪里根本不是问题。那段回信提供的信息量，比我自己在脑子里反复推演两天加起来还多。不是我突然聪明了，是环境替我把一部分不确定性削掉了。

## 报错往前挪一格

调代码的时候更明显。之前接口配置一直报错，我一开始的做法是盯着报错信息猜哪一层出了问题，猜完再改一版，改完再跑。后来换了个节奏：能改的最小一处先改掉，立刻跑，看新的报错是不是往前挪了一格。往前挪一格，说明这一层通了；没挪，就换下一处。整个排错过程从「我要理解这套系统」，变成了「我在和这套系统交换信号」，速度快了不止一倍。

这里要辨一句：agent 式迭代不是莽。莽是不看反馈继续冲，agent 是每一步都盯着反馈调整。真正的区别在于，你允不允许自己带着一个不完整的理解出发。人容易觉得「我还没懂，所以我不能动」，agent 的假设是「我就是通过动，才有可能懂」。**理解不是行动的前提，理解是行动的产物。**

保研这条路上这个逻辑到处都用得上：选方向不用等「想清楚自己喜欢什么」才开始，先去读三篇论文、听一场组会、发一封套磁信，环境回给你的那句话，比你在宿舍里再想一周有用。复习专业课也不用等「准备 fully」才去做题，先做一套，错在哪补哪，错误信息本身就是进度条。

## 一个当天能做的动作

今天先挑手头卡住最久的那件事——不是最重要的那件，是被「我还没想清楚」卡住最久的那件——跑一个最小的版本出来。写一段、发一次、改一行、点一下运行都行。让环境先回你一句话，剩下的下一轮再说。
