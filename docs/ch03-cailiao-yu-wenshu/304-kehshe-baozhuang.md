# 课程项目如何包装上简历

不是每个本科生都有一作论文，但几乎每个人都有课程设计。课设能不能写上简历？能，而且写得好的课设很能打。关键是「包装」两个字怎么理解——它不是吹牛，是换一种写法把同一件事的价值讲出来。

## 一个经典例子

一份流传很广的保研简历模板里有个例子我一直记着：一门机械类课程的课程设计，原题是「减速器设计」。写进简历时，项目名变成了**「减速器基于参数的可视化设计」**，描述大意是：独立开发基于参数的减速器设计模型，根据减速比、转速、尺寸等参数自动计算全部数据，并将数据自动更新到 CAD 软件，实现基于参数的可视化设计，加快设计迭代速度。

同一个课设，两种读法。第一种读法是「我完成了课程要求」；第二种读法是「我做了一个参数驱动的设计工具，解决了重复计算的问题」。信息量差了一个量级。

拆开看它做了什么，一共三步：

1. **换了名字**：从课程作业名（减速器设计）换成问题名（基于参数的可视化设计），突出你解决的技术问题，而不是你上过哪门课。
2. **补了动词**：开发、计算、更新、实现——写清楚你做了什么动作，而不是「参与了某课设」。
3. **落了效果**：自动更新、加快迭代——这件事带来了什么改变。

## 我怎么写自己的项目

我简历上的两项项目经历就是这么写的：一个基于 YOLO 的智能教学评估系统，一个基于并行计算的多智能体仿真。它们的底子都算不上「科研项目」，但写法完全按科研经历的骨架来：

- **研究问题**：这个系统面向什么问题？（真实课堂里教学状态难以量化 / 多机器人路径规划策略难以对比评估）
- **负责工作**：我做了什么？（行为识别模型训练与热力图可视化 / 系统设计、核心代码与批量实验）
- **结果**：做出了什么？（可用的评估模块 / 五种规模下的策略对比数据）

没有论文不是问题，这三行照样能传递「我会定义问题、会实现、会评估」的信号。面试官看本科生项目，看的是这个工作流是否完整，而不是成果发在哪。

## 包装的边界

有几个雷区要避开：

- **名字可以重写，事实不能重写。** 「基于参数的可视化设计」描述的每一句话都是那个课设真实做到的。如果你写「独立开发了分布式调度系统」而实际是本地单机 demo，面试一问细节就穿，穿的那刻连你简历上其他真东西一起陪葬。
- **别把课设写成科研项目。** 可以叫「项目」，别叫「科研项目」或暗示有课题支撑。老师一问「这是哪个课题组的」你就尴尬了。
- **团队项目写清角色。** 核心成员就写核心成员，然后把你负责的那部分写透。三人课设你只调了界面，就写界面背后的东西（为什么这么设计、遇到什么问题），一样能写出深度。
- **准备被追问。** 写上简历的每个课设，按第二章那篇「项目深挖」的四句话模板各备一套：一句话面试版、30 秒版、3 分钟版、逐问应答。课设被问穿的概率远高于论文，因为你对它的掌控时间更短。

## 什么时候该写，什么时候不该

有科研经历的人，课设让位——简历空间有限，论文和科研项目优先。课设上简历的最佳时机是大二大三：你还没攒出科研，课设就是你能拿出的最完整的工程证据，好好写它，同时赶紧去做真正的科研，让它将来退居二线。
