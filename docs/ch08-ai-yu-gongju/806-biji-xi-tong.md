# 笔记系统选型

笔记软件大概是所有工具里最容易被反复折腾的一类：Notion、Obsidian、飞书、语雀，每个都试一遍，每次迁移都要半天，最后发现真正记笔记的时间远少于研究笔记软件的时间。这一篇讲我怎么选、为什么停在现在的组合上，以及选型时真正该看的三个问题。

## 我的组合：Obsidian 存放，VS Code 操作

我的笔记全部是本地 Markdown 文件，放在一个 Obsidian 库里。Obsidian 负责的是「知识地图」：双链、关系图谱、全文检索，这些是它真正不可替代的部分。

但我日常写笔记、改笔记，很多时候不是在 Obsidian 里，而是在 VS Code 里。理由有四条：

1. **快捷键无缝。**作为程序员，VS Code 的操作已经长在肌肉记忆里。写代码和记笔记之间随时切换，不需要适应两套逻辑。Obsidian 的快捷键是另一套，切换就有成本。
2. **Git 原生支持。**Obsidian 的多端同步往往依赖付费服务或第三方插件，而 VS Code 对 Git 是原生级支持。所有笔记通过一行命令 push 到私有仓库，版本控制和多端同步一次解决，免费、可靠、出问题能回滚。
3. **插件够用。**配 Markdown All in One（快捷键和自动补全）、Markdown Preview Enhanced（预览）、Paste Image（截图直接粘贴进笔记）这几个插件，排版和预览体验不输 Obsidian。
4. **AI 集成顺。**在 VS Code 里可以直接调 AI 助手，让它在聊天面板里帮你梳理笔记结构、扩写、提问题。笔记和 AI 的距离越近，「边写边问」才越自然。

所以实际的分工是：**VS Code 负责写和同步，Obsidian 负责看和连。**同一批文件，两个入口，谁也不挡谁的道。

## AI 时代的第二条路：以资料为中心的笔记

除了自己写，还有一类「读进来的资料」。这类我现在的处理方式是用 NotebookLM 这类以资料源为核心的 AI 工具：把一批文献或网页丢进去，它基于且仅基于你给的资料回答问题、生成摘要。好处是回答有出处可查，不容易自由发挥；摘要、观点对比、跨资料提问，都比自己手动整理快得多。

我的边界划分是：**需要长期沉淀、自己消化的，进 Obsidian 库；临时性的资料问答和速读，交给 AI 工具，结论值得留的才抄进步记。**别把 AI 生成的所有东西都存下来——没经过自己改写的内容，存了也不会再看。

## 选型时真正该问的三个问题

回看我自己走过的弯路，选型错从来不是错在「功能不够」，是错在没回答这三个问题：

**第一，你的笔记是什么格式？**如果答案是 Markdown，选择面立刻收窄到本地文件系工具，迁移成本趋近于零。纯 Markdown 意味着任何编辑器都能打开，永远不会被某个软件绑架。

**第二，多端同步你打算怎么解决？**这是大多数人换软件的真实动因。我的答案是 Git：程序员本来就要用，顺路解决笔记，不引入新依赖。不想碰 Git 的，选有官方同步的，把这笔钱当作买断折腾时间。

**第三，这个工具坏了怎么办？**本地 Markdown 的答案是「无所谓」，换个编辑器接着用。云端工具的答案是「导出」，而多数人从不导出。这一条其实是在问：五年后你的笔记还在不在你手里。

## 够用就好

写到这里，这一篇其实已经在给 809 那篇工具观铺垫了。笔记系统的选型是我吃过最多亏的地方——换过四五个软件，每次都带走了知识，留下了重新归类的半天。最后停在 Obsidian 加 VS Code，不是因为它是客观最优解，而是因为它对我这个每天写代码的人来说，转移成本最低、迁移风险最小。

判断标准从来不是「哪个软件最强大」，是「哪个组合让你最愿意打开它」。笔记系统的价值在于你真的在用，而真的在用的前提是它足够顺手、足够 boring——boring 到你打开它的时候只想着内容，完全不用想软件本身。
