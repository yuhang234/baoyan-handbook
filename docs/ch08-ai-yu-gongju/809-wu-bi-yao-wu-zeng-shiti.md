# 如无必要，勿增实体

这一章前面讲了那么多工具——笔记系统、网盘、AI 工作流、刷题平台——收尾这篇想反过来说：工具的上限不在于你加了多少，而在于你养得动多少。「如非必要，勿增实体」这句话，我是从自己桌上六个输入设备悟出来的。

## 三个键盘的故事

有一阵子，我桌上有有线键盘、无线键盘、蓝牙键盘，还有麦克风、录音机、收音机。如果有人问我为什么要这么多，我能给每一个都找到理由：有线的稳定不掉线，无线的桌面干净，蓝牙的能连平板；麦克风录得清楚，录音机不开电脑也能记，收音机——收音机就是收音机。听起来每条都成立。

但把它们摆在一起看，答案就藏不住了：**我买的从来不是六个功能，是六份状态。**

功能是静态的，状态是活的。有线键盘要占一个接口，桌子后面多一根线；无线键盘要管接收器、记着换电池；蓝牙键盘要配对、要判断它现在连的是电脑还是平板；麦克风要选输入设备、调增益；录音机要记电量、导文件。功能只在你用它的时候存在，状态在你不用它的时候也存在——它在后台占着注意力。这些东西单看都小，加起来是一种持续的低强度心智负担。它不会突然爆掉，只是让你每次动手前都先做一段「准备工作」，而你已经习惯到不再把它算成成本。

我真正要的是什么？想打字的时候能打字，想说话的时候能被记下来。就两件事。六个实体服务两个需求。

## 多余的实体还要收「解释成本」

实体多起来之后，更隐蔽的一件事是：我开始需要解释它们。

我得跟自己解释为什么三个键盘各有存在意义，得在心里维护一套「什么时候用哪个」的分工规则。这套规则没写下来，但确实在脑子里运行着——而这套规则本身，就是为多余实体额外支付的利息。等真出了问题，键盘不出字、录音丢了一段，你要排查的不再是一个设备，而是一整套自编自演的分工体系。

所以「勿增实体」不是节俭美德，是为了让判断保持锋利：东西越少，出问题时可能的原因越少，你越快能指着一块说——就是这儿。

## 那把尺子：被问题逼出来，还是被想象逼出来

这句话很容易被用反，变成「什么都别加、维持现状最安全」。不对。语音记录这件事，我就是靠一个额外的设备把工作方式整个改掉的——我现在很多时候是说，不是打，这个改变每天都在发生，那这个实体就该留。

所以判据不是数量，是这一条：**这个实体是被问题逼出来的，还是被想象逼出来的。**被问题逼出来的，你能说清它解决了哪一次具体的失败；被想象逼出来的，你说清的只有「万一以后要用呢」。

放到操作上就是三步：

1. **盘点**：把每样工具按「最近一个月我用它做成过哪件具体的事」排一遍，写不出具体事件的，从桌面撤下——不用扔，从「随时可用」降级成「需要时再拿」。
2. **收敛**：同一类需求只留一条主路径。我录音用手机加输入法就够，麦克风和录音机降级为备用，文件不再散在三个地方。
3. **举证**：以后再想加任何东西——设备、软件、流程环节——先写一句话说明它解决了哪一次已经发生过的失败。写不出来就不加。

「如非必要」的重点从来不在「必要」上，在「如非」上：默认不加，要加，你举证。

还有一个中间步骤特别管用：遇到问题，先确认手上的东西有没有被用到极限，再决定加不加。大多数时候答案是「没有」——参数还是默认的，用法还是最粗的，我就已经在物色下一个了。这时候换工具等于跳过诊断直接换器官，新东西带来一点改善，病根却被永久埋起来。

## 呼应这一章的选型

回头看这一章的几个选择，其实都是这把尺子量出来的：笔记停在 Obsidian 加 VS Code，因为 Git 顺手解决了同步，不用再加付费同步服务；网盘三件套各管一段，没有第四个「以防万一」；转写用手机自带能力，faster-whisper 是在真有批量需求之后才上的。805 里那句「它有义务听懂我」，反过来对自己的工具也成立——是我驾驭工具的边界，不是工具驯化我的起点。

工具这章写到最后，结论朴素得像句废话：每一样新东西进来之前，先问它顶掉了哪一个旧问题。答不上来，就让它待在购物车吧。
