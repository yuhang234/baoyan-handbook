# 论文深度解析提示词

读论文最大的浪费不是读不懂，是读错顺序：拿到一篇三十页的论文从摘要顺着往下啃，啃到第四章才发现这工作跟自己的方向没关系。我的做法是先把「判断值不值」和「理解内容」分开——第一步让 AI 用五分钟给你一个速览，第二步再决定要不要精读。这一步用一个固定结构的提示词就能做到，下面这份我用了大半年，直接复制改两个占位符就能用。

## 完整提示词模板

```text
# Role
你是一位资深的学术教授和顶级期刊审稿人，拥有极强的逻辑分析能力和深厚的
学术功底。擅长从复杂的科研论文中快速提取核心创新点、评估方法论可靠性，
并能以简洁明了的方式向研究者解释复杂的公式和模型。

# Context
我正在阅读一份名为《请替换为论文标题》的科研论文（作者：作者；投稿期刊：
期刊）。我需要你作为我的学术助教，帮助我深度消化这篇论文的内容，以便我
能快速判断该工作的价值，并决定是否在其基础上开展后续研究。

# Goals
请阅读我提供的论文内容（或附件），完成以下任务：
1. 核心速览：用一句话概括这篇论文解决了什么问题，采用了什么核心方法，
   达到了什么效果。
2. 创新点分析：列出论文的 3-5 个核心创新点，并说明它们与现有工作的
   主要区别。
3. 技术路线拆解：
   - 详细解释模型架构/算法流程；
   - 如有复杂公式，请用通俗易懂的类比解释其物理意义或逻辑。
4. 实验评估：
   - 论文使用了哪些数据集？
   - 关键量化指标（如准确率、FPS、延迟等）表现如何？
   - 是否有对比实验和消融实验？结论是什么？
5. 批判性思考：
   - 该研究存在哪些局限？
   - 在实际工程落地中可能遇到哪些挑战？
6. 后续研究启发：基于这篇文章，有哪些值得进一步探索的方向？

# Constraints
- 必须基于论文提供的实际信息回答，严禁编造。
- 使用学术化但清晰的语言，避免过度堆砌术语。
- 采用 Markdown 格式输出，重要术语保留英文原文。
- 列表请统一使用 '- ' 格式。

# Workflow
1. 我将上传论文 PDF 或粘贴论文文本。
2. 请你先确认收到，并只给出第 1 项（核心速览）的内容。
3. 待我回复「请继续」后，再展开后续详细分析。
```

## 三个设计意图

这份模板不是随便堆的，每一段都在解决一个真实的失败案例：

**Role 段解决「口吻漂移」。**不指定教授/审稿人角色时，AI 默认用科普腔，把消融实验解释成「就是做个对比啦」。角色定了，输出的颗粒度就对了。

**Workflow 的分步确认解决「信息倾泻」。**让它一口气输出全部六项，常见结果是每项都浅尝辄止。先只要核心速览、你说「请继续」它才展开，等于强制它把力气花在你确认值得的地方。实践中这一步帮我省下的阅读量最大——速览看一眼，三成论文可以直接归档。

**Constraints 的「严禁编造」解决幻觉。**这条要写得越早越好、越具体越好。涉及数据集和指标数字时，我会再补一句「引用原文页码」，方便我回头抽查。

## 配合笔记系统怎么用

AI 的输出不要留在聊天窗口里，那等于没读。我的做法是在 Obsidian 里建一个「文献阅读」文件夹，每篇论文一个笔记，按这个骨架存：

| 维度 | 记什么 |
|---|---|
| 论文信息 | 标题、作者、年份、期刊 |
| 核心方法 | 一句话 |
| 性能指标 | 关键数字两三个 |
| 创新点 | 1–3 条 |
| 可借鉴点 | 能搬到自己工作里的部分 |
| 疑问 | 要去核对的原文页码 |

「疑问」一栏最重要：它是 AI 可能出错的地方清单，精读时优先核对。

## 两个追问技巧

- 公式看不懂时不要问「解释公式 3」，太宽。问：「请用 Python 代码逐行实现公式 (3) 的计算逻辑，并用一个 2×3 的小矩阵走一遍数值。」代码 + 小数值例子，比三段文字都清楚。
- 读到自己方向的论文时，在 Context 里加一句：「请结合我正在做的基于行为识别的课堂评估研究，分析这篇论文的技术哪些可以直接引入。」它会把解读视角从「这篇论文说了什么」切换到「这对你的工作意味着什么」。
