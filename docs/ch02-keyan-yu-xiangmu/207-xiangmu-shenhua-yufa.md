# 项目深挖：面试官如何追问你的项目

面试里项目环节的规律非常稳定：面试官从你的一句话介绍开始，沿着任何他不满意的点往下钻，直到钻到你答不出来为止。准备项目的意思，不是把项目介绍背熟，而是把钻的路径提前铺好。这篇用我自己的课堂识别项目当例子。

## 第一层：一句话版本

先给结论式的自我介绍，30 秒内讲完。我的版本：

> 我们做了一个基于改进 YOLOv11 的课堂行为分析系统：摄像头采集课堂视频，模型实时识别六类学生行为，结果在一块 ECharts 大屏上呈现实时占比、专注度趋势和异常预警。我负责数据处理、模型训练和改进模块的消融验证。

注意结构：做了什么、怎么做的、我负责哪段。没有形容词的空间。

## 第二层：三分钟版本，按四层展开

面试官说「详细讲讲」，就按固定顺序走：

1. **背景与问题**：传统课堂评价靠问卷和成绩，主观且滞后，所以想让行为数据说话。
2. **方法**：5 段真实课堂视频抽帧标了 1200 张图，六类行为标签，YOLO11m 加迁移学习训练，再加 BiFormer、Wise-IoU v3、ShuffleAttention 三处改进。
3. **结果**：Precision 0.871、Recall 0.832、mAP@0.5 0.865，边缘设备 25–30 FPS，消融实验逐条验证每个模块的贡献。
4. **不足**：低头看书和走神的边界靠标注规范硬性约定；样本量对遮挡场景仍偏小；没有做跟踪级别的个体行为序列。

不足这一层很多人跳过，但它恰恰是面试官判断你是不是真做过的地方——真做过的人知道自己的坑在哪。

## 第三层：追问，用固定模板接

任何实现细节的追问，都用四句话组织回答：

1. **目的**：这一步解决什么问题？
2. **方法/数据结构**：具体是怎么做的？
3. **落点**：在系统的哪个环节？
4. **取舍**：为什么这样做，代价是什么？

用我的项目演示两次：

**「为什么加 BiFormer？」** 目的：课堂里学生互相遮挡，小目标漏检严重。方法：在 backbone 里加 BiFormer 注意力，让检测聚焦遮挡区域的关键特征。落点：只动骨干网络，训练流程不变。取舍：计算量略增，所以最后用 FPS 验证没有伤到实时性。

**「mAP@0.5 是 0.865，这个数怎么来的？」** 目的：衡量六类行为的整体检测精度。方法：按 7:2:1 划分数据集，在验证集上按类别算 P-R 曲线下面积再取平均。落点：它是消融实验的基准指标，每个改进模块都和它比。取舍：0.5 是 IoU 阈值，说明定位精度到「框基本对」的程度，更细的评价还要看逐类混淆矩阵。

## 面试官最爱钻的五个方向

- **数据**：数据哪来的、多少量、怎么标的、标签边界怎么定？
- **指标**：这个数怎么算出来的、基线是谁、提升多少？
- **改进**：为什么是这个模块、消融怎么做的、有没有试过别的？
- **失败**：遇到过什么 bug、怎么定位的？
- **扩展**：如果数据翻十倍/换到新场景，你会怎么改？

准备方法就是把每个数字的来历写成一句话，把每个技术选择写成「目的—方法—落点—取舍」四行。完整的项目故事，见[课堂视觉识别项目全记录](209-classvision-xiangmu.md)和[流体仿真项目复盘](208-liuti-fangzhen-xiangmu.md)。

## 最后一条：不知道就承认

被钻到答不上的地方，就直说「这一块当时是同学负责/我没深入，我的理解是……」。编造会被下一个追问当场戳穿，诚实反而能把话题引回你准备过的区域。项目环节考的不是你知道多少，是你说的每句话可不可信。
