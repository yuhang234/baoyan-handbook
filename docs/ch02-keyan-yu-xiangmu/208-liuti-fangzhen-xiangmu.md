# 流体仿真项目复盘：从论文到 GPU 实现

这是我做过最「硬」的一个项目：用 Python 加 NVIDIA Warp，把一篇 2007 年的 SPH 论文实现成能在 GPU 上跑的流体仿真，再一路做到表面重建和渲染。四个任务递进，每个任务都是一次完整的「读论文—实现—验证」循环。

## 项目是什么

WCSPH（弱可压缩光滑粒子流体动力学）把流体表示成一群粒子，每个粒子带位置、速度、质量、密度、压强。每个时间步做五件事：用空间哈希网格找邻居 → 密度求和 → 用 Tait 状态方程把密度偏差换成压力 → 算重力和对称压力梯度 → 半隐式 Euler 更新速度位置。

四个任务的演进：

- **Task 1**：精读 Becker & Teschner 2007，整理 SPH/WCSPH 的公式和时间步流程，写成报告。这一步看起来不产代码，但后面所有实现都是照着它长出来的。
- **Task 2**：在给定的 TODO 骨架里补齐密度、状态方程、重力、压力加速度四类 Warp kernel，输出 USD 粒子动画。
- **Task 3**：不改求解器，只把初始流体从立方体换成球体/椭球体，加命令行参数和 PNG 快照——考验的是你有没有把「初始化」和「求解」解耦。
- **Task 4**：关键帧粒子导出 ASCII PLY，用体素化加 Marching Cubes 做 Python 预览，或进 Blender 用 Metaball 加水材质渲染。

## 几个关键参数，和它们为什么是这些值

| 参数 | 值 | 由来 |
| --- | --- | --- |
| 粒子间距 | 0.2 | 初始规则采样 |
| 光滑半径 h | 0.4 | 两个粒子间距 |
| 参考密度 | 1000 | 水的近似密度 |
| Tait 指数 γ | 7 | 液体刚性的经典取值 |
| 压强模量 B | 1,428,571 | rho0·c²/γ |
| 等效声速 | 100 | 决定时间步上限 |
| 时间步 dt | 0.0002 | 0.2/1000，稳定性约束 |

面试时我被问过「为什么 dt 这么小」：声速越大，压力波在一个时间步内传播的距离越不能超过光滑半径，这是显式积分的稳定性天花板。答出这个因果链，比背参数有用得多。

## 排错的两个真实瞬间

**粒子爆炸**。早期跑出来粒子四散飞溅。排查顺序是固定的：先查密度计算有没有清零重算，再查压力项符号——压力梯度必须用对称形式 p_i/ρ_i² + p_j/ρ_j²，写成单边形式会引入非物理净力，动量不守恒。最后还要检查重合粒子：两个粒子距离趋近零时梯度除零，代码里要有最小距离保护。这三层查完，问题基本都能定位。

**GPU 结果对不对**。Warp 同一套 kernel 可以在 CPU 和 CUDA 上跑，我的验证办法是先用 CPU 短时仿真 0.02 秒出快照，确认物理行为合理，再开 GPU 跑长仿真对比轨迹。另外做了基本数值保护：密度和压力下限、AABB 边界夹取、CUDA 失败回退 CPU。

## 诚实说不足（面试必考）

- 这是教学型 WCSPH，允许约 1% 密度波动，不是严格不可压缩（那要上 PCISPH/DFSPH）；
- 黏性只做了速度平滑，没有完整人工黏性、表面张力和真实黏度；
- 时间步固定，没有 CFL 自适应；边界是静态粒子加安全层的近似。

主动把不足讲清楚，再接一句「下一步会做密度修正和自适应时间步」，比等着被追问体面得多。

## 这个项目给我带来了什么

它是我第一次把一篇英文论文完整翻译成可运行、可验证的代码。后面做课堂行为识别时，读论文、复现、逐个模块验证的套路完全一样——科研里真正可迁移的能力，就是这套循环。
