# 计算机组成原理面试题

组成原理在面试里的题量比不了数据结构和网络，但有几道经典必考：存储层次与 Cache、流水线、补码与浮点。这一科的题答好了很出挑，因为多数人复习顺序把它排在最后。

## 冯·诺依曼体系：一切的起点

**主问题：什么是冯·诺依曼体系结构？计算机由哪几部分组成？**

骨架：运算器、控制器、存储器、输入、输出五大部件 → 核心思想两条：指令和数据都以二进制存于同一存储器、按地址访问、顺序执行 → 追问指令和数据怎么区分——靠取指阶段和执行阶段的上下文（取指周期取出的是指令，执行周期取出的是数据），CPU 内部用不同的信号通路区分。

追问与陷阱：冯·诺依曼瓶颈（指令和数据共享一条通路，速度受限）→ 哈佛结构（指令、数据分存储器分通路）——现代 CPU 是改良版：片内 L1 分指令缓存和数据缓存，片外统一主存，能把这对概念讲清的寥寥无几。

## 存储层次与 Cache：必考核心

**主问题：存储器为什么分层？什么是局部性原理？**

骨架：寄存器 → L1/L2/L3 Cache → 内存 → 外存，速度递减容量递增 → 矛盾是快的贵、大的慢 → 靠程序局部性填平：时间局部性（刚访问过的马上还会访问）、空间局部性（访问了一个地址，旁边的也快了）→ 所以把热点数据放进 Cache，命中率一高，平均访问时间就贴近 Cache。

**Cache 映射方式**：直接映射（主存块只能进唯一行，硬件最简、冲突率高）、全相联（任意放，最灵活、比较器贵）、组相联（组间直接、组内全相联，折中，主流 CPU 的选择）。

**追问与陷阱**：写策略——写直达（同步写回内存，简单但慢）与写回（只改 Cache 标脏位，替换时才写回，高效但复杂）；替换算法 LRU 及其近似实现；「怎么提高命中率」这类开放题从局部性答起：数据布局、循环顺序（行优先遍历二维数组是经典例子）。

失分点：只背「Cache 是高速缓存」，说不出它为什么有效——局部性原理才是这题的灵魂，没有它 Cache 就是赌徒。

## 流水线与冒险

**主问题：什么是流水线？流水线冒险有哪些？**

骨架：把指令执行切成取指、译码、执行、访存、写回多段，各段并行处理不同指令 → 提吞吐率不提单条延迟 → 三类冒险：结构冒险（硬件部件争用，如指令和数据存储器冲突）、数据冒险（后一条要用前一条的结果）、控制冒险（分支指令改变取指流向）。

追问与陷阱：数据冒险的解决——转发/旁路把结果直接从上一条送到下一条的入口，解决不了就插入气泡（stall）；控制冒险的解决——分支预测（静态预测和动态预测，答出「分支预测失败要冲刷流水线」就够）；RISC 为什么适合流水线——指令定长、格式规整。

失分点：说「流水线让一条指令变快了」——单条指令的延迟没变甚至略增，变快的是吞吐率，这个表述错误老师一追一个准。

## 数的表示：补码与浮点

**补码**：骨架：正数三码合一；负数补码 = 反码 + 1 → 为什么用补码：减法变加法，加法器一套电路通吃加减；0 只有一种表示；多表示一个最小负数。追问补码的数学本质——模运算，加 2ⁿ 等价于取负，能讲到这层的是真理解。

**IEEE 754 浮点**：骨架：符号 + 指数 + 尾数三段 → 为什么 0.1 + 0.2 != 0.3：二进制无法精确表示 0.1，尾数位数有限必然舍入 → 由此引出「浮点数不能直接用 == 比较」的工程常识。

**进制转换**：二、八、十六进制的转换要现场算，除基取余和按权展开两个方法都要熟，有的面试官真的会让你转一个数。

## 中断、总线与 I/O

**中断全过程**：骨架：中断请求 → 判断响应条件（屏蔽字、优先级）→ 断点保护（PC、状态寄存器压栈）→ 取中断向量进服务程序 → 恢复现场返回。追问中断嵌套——高优先级可打断低优先级，现场要逐层保护。

**DMA**：成批数据外设与内存直传，CPU 只做初始化和结束处理 → 三种 I/O 方式的演进：程序查询（CPU 空转等待）→ 中断（CPU 被打断后处理，适合低速设备）→ DMA（CPU 几乎不参与，适合高速成块传输），把演进线讲出来比背定义高一分。

**总线与大端小端**：总线是公共通信干线，分数据、地址、控制三类；大端是高位字节放低地址（符合人的书写习惯），小端相反（x86 家族），追问怎么用程序判断本机字节序——用联合体或指针强转看第一个字节。

组成原理的答题要点和别的科目不同：它考「机制」多于「名词」。同样是 DMA，背下「直接存储器访问」五个字没用，能画出「外设—DMA 控制器—内存」这条通路、说清 CPU 何时让出总线，才算过关。复习时对每个概念多问一句「数据/信号是怎么流的」。
