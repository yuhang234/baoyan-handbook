# 简历与科研项目深挖

简历深挖是整场面试里你最可控也最不可控的部分：可控在于问题全来自你自己写的那一页纸，不可控在于你永远不知道老师会从哪个词往下挖。这篇把追问整理成一棵树——面试官的提问路径其实相当固定，照着树把每条枝走到叶子，简历上的每个词才算真正属于你。

## 通用主干：所有项目都会走到的六层

不管简历上写的是科研、课设还是实习，老师基本都沿这条路径往下问：

1. **定位层**：用一句话讲清这个项目是什么、解决什么问题。骨架：面向什么对象 → 在什么条件下 → 做成了什么。这一层答不干净，后面全是沙地。
2. **角色层**：你具体负责哪部分，工作量占比多少。多人项目必被问分工，回答要具体到模块和文件，不要说「我们都参与了」。
3. **选型层**：为什么用这个技术栈/模型/算法，而不是另外两三个候选。这层考的是你有没有做过决策，只当过搬砖工的人在这里露馅。
4. **难点层**：最大的困难是什么，怎么定位、怎么解决的。骨架：现象 → 排查过程 → 解决动作 → 之后的验证。
5. **结果层**：量化指标。检测项目就是 mAP、FPS，预测项目就是误差降幅，没有数字的项目在老师眼里等于没做完。
6. **反思层**：重新做一次你会改什么。这层答得好反而能翻盘，它证明你不是执行完就忘了。

## 科研项目的分支：论文必被追问的五个点

我自己那篇在稿论文在面试里被问烂了，梳理下来追问集中在五处：

- **真实性**：「这是你自己写的吗？」——最好提前备着只有作者才知道的细节：审稿意见有几条、每条怎么回的、哪个实验结果推翻过初版设计。
- **设计动机**：「为什么用这个损失函数/评价指标？」——答「别人都用」等于零分。骨架：任务特点 → 指标衡量了什么 → 为什么它和任务目标对齐。
- **实验对比**：「和哪些方法比的？差在哪个环节？」——要能报出对比方法的名字和大致结果，说不全就说记得的部分，别硬编。
- **分工边界**：合作论文必问「你做了哪部分」。把边界划清楚：我负责数据与实验，方法设计是和导师讨论定的——诚实反而可信。
- **失败经历**：「投出去被拒过吗？」在稿就说在稿、审到哪一轮，没被问录用与否就不要主动许诺「一定能发」。

## 课程项目的分支：两个杀伤力最大的问题

课程项目（课设、大作业）看起来朴素，但有两个专属陷阱：

**「这是不是照着教程做的？」** 回答骨架：承认教程或既有实现的起点 → 讲你自己加的东西（换了数据集、改了结构、补了工程化的部分）→ 用细节证明动手深度。完全照做和全盘原创之间，有巨大的诚实空间可以用。

**「这门课教了什么，你的项目用到了哪部分？」** 这是课设项目特有的回连题，考你有没有把课内知识和动手内容接起来。准备方法：每个课设写一句话说明它对应哪门课的哪个知识点。

## 实习经历的分支：面试官在验证什么

有实习的同学会被问三件事：业务背景（这个模块服务什么场景）、你的实质贡献（离开你项目会不会停摆，诚实回答）、为什么离开（回答学业优先即可，不要抱怨前东家）。

## 答不上来时的诚实应对

追问树走到叶子答不出来，是正常现象——老师就是在找你的边界。三条应对：

1. **第二次换角度，第三次直接降级。** 「这个点我理解不深，我目前的理解是……如果有偏差请老师指正。」这句话不丢分，重复三遍同义答案才丢分。
2. **不编造名词。** 编出来的术语老师一听就知道，而且会追到底。承认不会，然后主动把话题拉回相邻的、你扎实的区域：「这块我没深入过，但类似的 X 问题我处理过，是这么做的。」
3. **事后记录。** 每场面试答不上来的问题当天记下来补掉——它们几乎必然在下一场再出现。我的面试复盘就是这么攒出来的，翻车复盘那篇（502）里的卷积核事故，最后变成了我后面每场面试的送分题。

最后提醒一句：简历上的每一行都是你签名确认过的声明。写之前问自己「这个能不能撑住三层追问」，撑不住就删掉——简历越短，深挖越安全。
